### Détail des correctifs

#### S1 — RLS permissive (advisor Supabase, ~20 tables)
Toutes les policies `*_all_auth` sont `FOR ALL … USING (true) WITH CHECK (true)` :
tout compte authentifié lit/écrit **toutes** les lignes, tous clients confondus
(`campaigns.client_nom`). Advisor : `rls_policy_always_true` × 18 + `is_admin()`
SECURITY DEFINER exécutable + 2 fonctions `search_path` mutable + leaked-password off.
**Correctif** : migration `web/supabase/migrations/0046_*.sql` restreignant les
policies d'écriture (INSERT/UPDATE/DELETE) à un périmètre (`created_by` / rôle admin),
`SET search_path = ''` sur les 2 fonctions, `REVOKE EXECUTE … is_admin` de `authenticated`.
**JAMAIS appliqué en prod sans validation Paul** (contrainte cadrage : touche RLS/données).
**Test** : 2 users distincts → `select count(*) from leads` renvoie chacun son périmètre.

#### S2 — Dump PII dans git
`backups/renoleads_icestream_full_dump.json` (271 Ko, tracké) contient 188 entreprises
avec téléphones/emails de dirigeants (PII RGPD). **Correctif** : `git rm --cached`,
`backups/*.json` ajouté au `.gitignore`. **Purge de l'historique** (`git filter-repo` +
force-push) = action destructive → validation Paul explicite requise.
**Test** : `git ls-files backups | grep -c json` = 0.

#### S3a — Streamlit fail-open
`app.py:195` : si `APP_PASSWORD` absent (ou lecture en échec, `except: return None`),
l'app démarre **ouverte**. **Correctif** : fail-closed par défaut, échappatoire explicite
`APP_ALLOW_OPEN=1` pour le dev. **Test** : `_require_auth` env vide → `st.stop()`.

#### S3b — SSRF scraper
`scraper.py:421` `session.get(url, allow_redirects=True)` où `url` vient de `lead.site_web`
(hostile). Un `http://169.254.169.254/…` est fetché depuis le worker porteur de
`service_role`. **Correctif** : résoudre l'hôte, rejeter IP privée/loopback/link-local/reserved,
schéma `http/https` uniquement. **Test** : `_construire_base_url("http://127.0.0.1")` → `None`.

#### S3c — robots.txt sans timeout
`scraper.py:397` `rp.read()` (`urlopen` sans timeout) fige le thread sur un serveur
tarpit ; heartbeat continue → run « vivant mais mort ». **Correctif** : fetch via
`session.get(robots_url, timeout=…)` puis `rp.parse(...)`. **Test** : mock `Timeout` → pas de blocage.

#### S3d — Secrets en query string
`req.nextUrl.searchParams.get("secret")` : le secret finit dans les access logs Vercel /
Referer. **Correctif** : n'accepter que via header (`Authorization: Bearer` / `x-webhook-secret`).
⏸ Touche l'auth des webhooks entrants (Twilio/Instantly/cron) → validation Paul (risque de
casser les intégrations si l'appelant envoie encore en query). **Test** : `?secret=` → 401 ; header → 200.

#### S3e — bornes/ingest ouvert
Tout user connecté peut relancer une ingestion IRVE de 300 s. **Correctif** : réserver aux
admins + throttle (refuser si ingestion `< N min`). ⏸ Touche rôle/auth → validation Paul.

#### S4a — Comparaison de secret non constante
Réutiliser le helper `safeEqual` (crypto.timingSafeEqual) déjà présent dans
`calendly/webhook/route.ts` pour toutes les comparaisons de secret partagé.

#### S4b — `ilike(email)` → `eq(email)`
`webhooks/instantly/route.ts:65` : `%` dans l'email matcherait un lead arbitraire.
**Correctif** : `.eq("contact_email", email)`. **Test** : payload `email:"%"` → `matched:false`.

#### S4c — Détails d'erreur au client
Renvoyer un message générique client, logger le détail serveur. **Test** : erreur → réponse sans stack.

#### S4d — SMTP sans timeout
`mailer.py:143` `smtplib.SMTP(host, port)` → ajouter `timeout=20`. **Test** : `grep SMTP( | grep -v timeout` vide.

#### S4e — Path traversal `session_id`
Helper `_dossier_session` : `resolve()` + `is_relative_to(OUTPUT_ROOT)` sinon `ValueError`.
**Test** : `read_session("../..")` → erreur, pas de lecture disque.

#### S4f — PII dans diagnostics
`client.py:126,189` : `resp.text[:200]` (corps Dropcontact) peut écho­rer prénom/nom du
dirigeant dans `runs.erreur`/heartbeat. **Correctif** : ne garder que `status_code` + champ
`error`/`reason` JSON. **Test** : mock 400 avec « Jean Dupont » → message sans « Dupont ».

#### S5a/S5b/DEP — reportés
- S5a HMAC natif Twilio/Instantly : le secret partagé fail-closed est acceptable ; aligner
  sur le HMAC Calendly = amélioration, non bloquant.
- S5b Zod : les routes valident manuellement + RLS/secret en amont ; hardening progressif.
- DEP postcss : le seul `npm audit fix` disponible force `next@9.3.3` (downgrade majeur
  cassant, faux positif de plage). Surface = XSS au stringify CSS (build), pas exploitable
  runtime user. Reporté jusqu'à un `next@15.x` patché.

## 📊 Rapport final

**Fermées (livrées + testées, CI verte) — 15 constats :**
- Sécu : S2 (retrait suivi), S3a, S3b, S3c, S4a, S4b, S4c, S4d, S4e, S4f — 10 commits `fix(sec)`.
- UX : U1, U2, U3, U4, U5, U7, U8, U9, U10, U12 — 5 commits `feat(ux)`.
- Tests : **1077 pytest** verts + tests de fermeture ajoutés par faille ; `tsc --noEmit` vert ; `ruff` vert.

**En attente de validation Paul (⏸) — 4 constats :**
- **S1** : migration `0046` déposée (search_path fixé ; gabarit RLS scoping commenté).
  Décision requise : modèle de tenance (par-commercial `created_by` vs équipe-partagée)
  avant d'activer le scoping. Leaked-password + is_admin = notes dans la migration.
- **S2 (purge historique)** : `git filter-repo` + force-push = action destructive.
- **S3d** : passer les secrets webhook/cron en header only — risque de casser
  Twilio/Instantly/cron si l'appelant envoie encore en query.
- **S3e** : gating admin + throttle sur `bornes/ingest`.

**Reportées (⏭, non bloquantes) — 5 constats :**
- S5a (HMAC natif Twilio/Instantly), S5b (Zod généralisé), DEP (postcss/next — le
  seul fix force un downgrade majeur cassant), U6 (extraction `Stat`), U11 (polish couleurs).

**Non reproduit (❌) :** aucun — tous les constats de l'audit ont été confirmés dans le code.
